# Собеседование Java-Backend в реальном времени (Spring Boot + Vosk ru-0.42)

Стажёр говорит в микрофон → Vosk распознаёт на лету → как только ответ закончился, система за доли секунды
решает: **задать уточняющий вопрос или перейти к следующему**. После последнего вопроса — итоговая оценка
по 4 критериям.

## Запуск
1. Модель — в `models/vosk-model-ru-0.42/` (внутри `am/`, `conf/`, `graph/`, `ivector/`) или `VOSK_MODEL_PATH`.
2. `mvn spring-boot:run` (или `VoskSttApplication` в IntelliJ). Дождитесь `Started VoskSttApplication`.
3. Откройте http://localhost:8080/interview.html (демо «речь → текст» — http://localhost:8080).
   Лучше в наушниках: иначе микрофон услышит озвучку вопроса.

## Как устроено быстрое решение
Нет LLM и нет обращений к сети на критическом пути. Всё тяжёлое посчитано при старте.

```
микрофон ─50 мс кадры─► WebSocket ─► Vosk (partial)  ─┐
                                    └► VAD: тишина ≥ N мс ─► ENDPOINT ─► разбор ответа (~10 мкс) ─► решение ─► вопрос
                                                                                   └─ после отправки: финальный текст Vosk для отчёта
```

| Этап | Время | Как оптимизировано |
|---|---|---|
| Ожидание тишины (конец ответа) | **450 мс** мягкий конец + 150 мс до решения «дальше» (≈ 0,6 с); для уточнения — дольше, см. «Синхронизация» | свой энергетический VAD вместо ожидания собственного endpoint Vosk (≥0.5–1 с); после союзов («и», «потому что») и очень коротких фраз порог автоматически больше — чтобы не обрывать паузу посреди мысли |
| Разбор ответа + решение | **≈ 10 мкс** (p50), ≈ 40 мкс (p99) на 80 слов | банк вопросов предкомпилирован в `int[]`; хеши основ слов вместо строк; примитивная хеш-таблица; ни регулярок, ни аллокаций в цикле |
| Финализация Vosk (`getFinalResult`) | вне критического пути | решение отправляется **до** финализации; точный текст нужен только итоговому отчёту |
| Холодный старт | прогрев при запуске | `warmUp()` прогоняет «интервью» для JIT; Vosk прогревается 2 с тишины |

Итого решение приходит примерно через `end-silence-ms + 0.05 мс` после последнего слова. Для цели 0.6 с
оставьте 450 мс; для более осторожного режима (меньше ложных обрывов) поставьте 600–700.
Цифры по разбору ответа измерены на заглушке-песочнице; задержку Vosk с моделью 1.8 ГБ и сеть смотрите на
своей машине: в каждом событии `decision` приходит `timing` (`silenceMs`, `decisionMicros`, `serverMs`).

## Логика «уточнить или дальше» (`DecisionPolicy`)
Покрытие = доля ключевых понятий эталона (взвешенная по IDF), уже названных в ответе (накопительно по уточнениям).

| Условие | Решение |
|---|---|
| ответа нет / «не знаю» | дальше |
| покрытие ≥ порога уровня (Стажёр 0.40, Junior 0.45, Middle 0.50, Senior 0.55) | дальше |
| лимит уточнений (`max-follow-ups`, по умолчанию 2) | дальше |
| уверенно, но не по теме | дальше |
| уточнение ничего не добавило | дальше |
| иначе | **уточняющий вопрос** — тот из 4–5 вариантов банка, что бьёт в ещё не названные понятия |

## Итоговая оценка (`InterviewScorer`)
Каждый критерий 0–10 по каждому вопросу, затем среднее по вопросам. **Итог = (c1+c2+c3+c4)/4**, то есть сумма
четырёх критериев, нормированная к максимуму 10, округление до 0.01 (считается по округлённым критериям).

1. **Развёрнутость и полнота** = 10·(0.75·покрытие + 0.25·длина ответа относительно целевой).
2. **Техническая грамотность** = 10·(0.6·покрытие «ядра» + 0.25·доля технических слов по теме + 0.15·покрытие) · (1 − штраф за слова-паразиты и неуверенность).
3. **IT-термины и сленг** = разнообразие и плотность терминов из `glossary.txt` (80%) + различные слова сленга за интервью (20%).
4. **Скорость** = 0.6·быстрота начала ответа (1.5 с без штрафа, до 0 к 19.5 с) + 0.4·темп речи (90–180 слов/мин идеально) — умножается на коэффициент содержательности (0.3…1), чтобы быстрый «не знаю» не давал баллов.

## Английские слова: распознавание и озвучка

**Проблема.** Русская модель Vosk почти не знает английского: «HashMap» она пишет как «хеш мап», «хешмеп» или вовсе мимо.
А русские голоса браузера читают «HashMap» как «хашмап» или по буквам. Решено в три слоя.

**1. Понимание терминов (`TermNormalizer`)** — сравнение «по звучанию». Слова сводятся к звуковому скелету (согласные в
общем русско-английском алфавите): «хэш мап», «хешмеп», «hashmap» → `hSmp`; «спринг бутт» → `sprngbt`; «эс кью эль» → `skl`.
Поэтому не нужно перечислять все варианты написания. Работает так:
* анализатор получает каноническое имя термина → термин засчитывается, даже если Vosk написал его по-своему;
* на экране английские имена возвращаются в латиницу («хешмеп» → `HashMap`, «джи ви эм» → `JVM`), а обычные русские слова не трогаются;
* защита от ложных срабатываний: служебные слова не склеиваются в термин («джава это» ≠ `JWT`), родные русские слова ищутся только точно («запуск» ≠ `List`). Тест `russian_prose_of_the_bank_has_no_false_phonetic_rewrites` проверяет это на всех эталонах банка.

**2. Второй проход Whisper (необязательно, `tools/whisper_server.py`).** Whisper понимает смесь русского и английского и принимает
подсказку: в неё кладутся термины из `glossary.txt`, поэтому «HashMap» он пишет латиницей. Работает ПОСЛЕ решения (на скорость реакции
не влияет): точный текст заменяет текст Vosk в итоговой оценке и показывается в журнале (зелёная строка «✎ уточнено»).
Нет сервера или он упал — интервью идёт на Vosk как обычно.
```
pip install faster-whisper
python tools/whisper_server.py --model small                  # CPU; первый запуск скачает ≈460 МБ
python tools/whisper_server.py --model medium --device cuda --compute-type float16   # с видеокартой NVIDIA — точнее
```
Затем в `application.yml`: `interview.whisper-url: http://localhost:9000/transcribe` (или переменная `WHISPER_URL`).

**3. Озвучка (`SpokenText` + `spoken.txt`).** Перед чтением вслух английские термины заменяются русским произношением:
«HashMap» → «хэшмэп», «JVM» → «джей-ви-эм», «N+1» → «эн плюс один». На экране остаётся оригинал. Словарь `spoken.txt` покрывает ВСЕ
английские слова всех 299 озвучиваемых вопросов (тест это проверяет); для новых слов есть запасные правила (аббревиатуры — по буквам,
остальное — транслитерация), а `SpokenText.unknown()` покажет, что стоит добавить в словарь.

**Голос.** На странице есть выбор голоса, скорость и кнопка «Проверить голос». Автоматически выбирается лучший из доступных:
нейронные «Natural/Online» (в Microsoft Edge — Svetlana, Dmitry; нужен интернет), затем «Google русский», затем локальные Windows-голоса.

## Excel-отчёт по окончании интервью
Когда интервью закончилось (весь список или кнопка «Завершить»), в папке `reports/` создаётся файл
`Interview_<дата>_<кандидат>.xlsx`; на странице появляется путь и кнопка «Скачать». Имя кандидата вводится на стартовой странице.
Пример оформления — `docs/sample-report.xlsx` (на демо-данных).

| Лист | Что внутри |
|---|---|
| **Сводка** | итоговая оценка и вердикт, 4 критерия (формулы) с цветовой шкалой и диаграммой, автоматическое резюме, итоги по уровням и по темам (от слабых к сильным, с диаграммой), ключевые понятия, которые чаще всего не прозвучали |
| **Вопросы** | строка на вопрос: исходный вопрос, ответ кандидата, уточняющие вопросы и ответы, покрытие эталона, **что прозвучало и что не прозвучало** (★ — ядро), термины и сленг, 4 оценки + итог по вопросу, комментарий системы; фильтры, закреплённая шапка, цветные оценки |
| **Диалог** | хронология «вопрос → ответ»: время, слов, время до начала речи, длительность, темп речи, источник текста (Vosk / Whisper), покрытие после ответа, решение системы |
| **Понятия** | каждое ключевое понятие каждого вопроса: вес, ядро или нет, прозвучало или нет (фильтр, зелёное/красное) |
| **Эталоны** | вопрос, эталонный ответ, критерии из банка, варианты уточнений (✓ — какие задавались) |
| **Методика** | как считаются оценки, пороги по уровням, настройки этого интервью |

Итоги на «Сводке» — **формулы** над листом «Вопросы»: поправите оценку вручную — итоги пересчитаются.
Файл создаётся без внешних библиотек (собственный генератор `export/XlsxBook`); формулы проверены пересчётом в LibreOffice.

Настройки: `interview.reports-dir` (папка), `interview.report-download` (кнопка «Скачать» на странице).
**Внимание:** в отчёте есть эталонные ответы банка. Если кандидат сидит за тем же компьютером, поставьте `report-download: false` —
файл всё равно сохранится в `reports/`, а на страницу попадут только оценки (эталоны в браузер не отправляются).

## Синхронизация: не перебивать и не терять слова
**Что было не так.** Конец ответа определялся по одной тишине (0,45 с), а для неполного ответа ждали ровно столько же, сколько для
законченного. Паузу «подумать» система принимала за конец, бросала уточнение, а микрофон до конца озвучки закрывался — продолжение
ответа терялось. Решение принималось по «отстающему» промежуточному тексту, поэтому ответ выглядел неполным.

**Как теперь.** Конец ответа проходит три стадии, и на каждой можно продолжить говорить:

| Стадия | Когда | Что происходит |
|---|---|---|
| 1. Мягкий конец | тишина ≈ 0,45 с | распознавание **дожимается** (flush), текст полный; готовится *предварительное* решение — но не принимается |
| 2. Жёсткий конец | + пауза по решению | **достаточный** ответ: +0,15 с (**≈ 0,6 с** всего); «не знаю», не по теме: +0,6 с; **неполный → уточнение: +1,5 с (≈ 2 с)**. Если речь возобновилась — предварительное решение отбрасывается, текст копится дальше |
| 3. Окно отмены | 1 с после решения | следующий вопрос приходит сразу, но клиент показывает и озвучивает его **только после окна**; микрофон открыт. Продолжили говорить — решение **откатывается** (`retract`), вы договариваете на прежний вопрос |

Уточнение выдерживает паузу дольше всего намеренно: именно после неполного ответа человек чаще всего просто думает.
Если хочется быстрее — уменьшайте `follow-up-extra-ms`; если система всё ещё перебивает — увеличивайте.

**Не теряются слова.** Микрофон открыт до самого показа следующего вопроса; текст для решения берётся после flush (а не из отстающего
промежуточного); решение, отменённое откатом, не оставляет следа в отчёте; устаревший результат Whisper игнорируется.
**Режим «🎧 я в наушниках»:** микрофон открыт и во время озвучки вопроса (можно отвечать, не дожидаясь конца); время озвучки не
засчитывается в «скорость ответа». Без наушников не включайте: микрофон услышит колонки.
**Контроль «успевает ли распознавание».** Если Vosk обрабатывает звук медленнее, чем он поступает (тяжёлая модель на слабом процессоре),
текст отстаёт и слова теряются. Сервер это замечает и показывает предупреждение (`asr_slow`, в решениях есть `asrRealtimeFactor`).
Лекарство: `vosk-model-small-ru-0.22`, закрыть тяжёлые программы.

Настройки (`application.yml`): `end-silence-ms`, `next-extra-ms`, `other-next-extra-ms`, `follow-up-extra-ms`, `grace-ms`.
Клиентскую логику (отложенный показ, отмена, устаревшая озвучка) проверяет `node src/test/js/interview-client-test.js`.

## Ограничения (честно)
* Оценка **лексическая**: ищет ключевые понятия эталона и их синонимы из словаря. Она не проверяет, что сказанное *верно*, и хуже видит сильное перефразирование. Для глубокой проверки можно добавить LLM **после** интервью (вне критического пути).
* Vosk по-прежнему не знает английского: фонетический слой исправляет типичные искажения, но если Vosk выдал совсем не похожее слово, поможет только Whisper (п. 2). Словарь `glossary.txt` (≈250 записей) — главный рычаг качества: по логам интервью добавляйте термины. Фонетика работает для терминов с ≥4 согласными в звуковом скелете; короткие («GC», «ORM») полагаются на точные варианты в словаре.
* Качество голоса зависит от браузера и ОС; «Natural»-голоса работают через интернет. Полностью офлайн-озвучка (например, Piper) в проект не входит.
* Пороги и веса откалиброваны на синтетических ответах (сильные / средние / слабые / не по теме), не на живых людях. Прогоните 5–10 реальных интервью и поправьте.
* Основа слова усекается до 6 букв: редкие ложные совпадения («контроль» ~ «контроллер») возможны.
* Vosk не выдаёт слоги; минимальная единица — слово.

## Настройка банка вопросов
`python tools/xlsx_to_tsv.py ваш_файл.xlsx` → перезапишет `src/main/resources/interview/questions.tsv`.
Или укажите внешние файлы: `interview.questions-path`, `interview.glossary-path`.

## Тесты — `mvn test`
Без модели: `TokenizerTest`, `EndpointDetectorTest` (синтетическое аудио), `InterviewFlowTest` (весь опрос на 50 вопросов,
границы оценок), `LatencyTest` (разбор < 1 мс), `LiveInterviewTest` (весь конвейер с подменённым Vosk: решение через ~450 мс тишины, озвучка, второй проход),
`SpokenTextTest` (весь банк озвучивается без латиницы), `TermNormalizerTest` (исправление терминов и отсутствие ложных замен),
`WhisperHttpTranscriberTest` (клиент Whisper на настоящем локальном HTTP-сервере), сценарии синхронизации в `LiveInterviewTest` (пауза посреди ответа, откат в окне отмены, конец списка, тормозящее распознавание),
`ExcelReportTest` / `ReportFilesTest` (корректность пакета xlsx, значения формул, пустое интервью, безопасные имена файлов).
С моделью: `SpeechSessionModelTest` (потоковое распознавание `test-ru.wav`).

## Структура
- `interview/engine` — чистая Java без зависимостей: токенизатор, словарь, предкомпиляция банка, анализатор, политика, VAD, сессия, оценка
- `interview/live` — `LiveInterview` (микрофон → решение), `SpeechEngine` (+ `VoskSpeechEngine`)
- `interview/web` — WebSocket `/ws/interview`, настройки, `ExcelReportService` + `ReportController` (скачивание `/api/reports/...`)
- `interview/export` — генератор Excel: `XlsxBook`/`XlsxSheet` (формат), `InterviewExcelReport` (содержимое), `ReportFiles` (имена файлов)
- `vosk/*` — распознавание Vosk (+ демо `/ws/stt`)
- `interview/engine/TermNormalizer`, `SpokenText` — исправление терминов и озвучка; `interview/live/WhisperHttpTranscriber` — клиент Whisper
- `tools/whisper_server.py` — необязательный сервер Whisper; `tools/xlsx_to_tsv.py` — конвертер банка вопросов
- `static/interview.html`, `static/pcm-worklet.js` — страница и захват микрофона
